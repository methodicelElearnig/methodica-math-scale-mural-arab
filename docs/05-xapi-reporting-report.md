# methodica-math-scale-mural-arab — conversion to the mafmar pattern (2026-11-01)

The Arabic build received every change made the same day to its Hebrew twin
(`methodica-math-scale-mural`, see that repo's `docs/05-xapi-reporting-report.md` for the reasons behind each
decision: scoring = the code, slide5 at weight 0, options by metadata index, drag-and-drop timing). This file
records only what differs.

## The second-component rule

Per `MOODLE-CONVERTED-UNIT.md` §15 (as in gaming-app-arab and the initial-mapping Arabic units), the Arabic
build is the **second component of the Hebrew unit**:
- unit `methodica-math-scale-mural`: `XAPI_UNIT_ID` and `metadata/methodica-math-scale-mural_unit.json` are the
  Hebrew ones, byte for byte (the Kata send re-PATCHes the unit with that same record);
- component `…/720/math/mafmar/methodica-math-scale-mural-arab-01/`, `order: 2`, `languages: ["Arabic"]`;
  every other component field equals the Hebrew component.

## Metadata

The delivered record (`docs/delivered-metadata-2026-10-28/`, dated 2026-10-28) had the older separate-unit
shape: ids under `…/720/ar/math/scale-mural/01/methodica-ar-math-scale-mural-01-01/…/index.html`, question
ids `index.html?q=qN`, an Arabic unit `methodica-ar-math-scale-mural-01`. It was rewritten:
- ids → `…/mafmar/methodica-math-scale-mural-arab-01/…-arab-01-NNN/` and `/qN`; `learningUnitId` → the Hebrew
  slug; `order` 1 → 2; its Arabic unit record is not used;
- the Hebrew unit's two content fixes applied: 003/q1–q2 `true-false` → `choice` (answers `نعم`/`لا`), and the
  `informationToBot` of 003 and 009 (it is Hebrew, as the family rule wants) corrected the same way;
- titles, question texts and answers are kept as delivered. Every choice answer equals the on-screen option
  text; the Q1/Q7/Q7b targets equal the chips; the correct answers equal the engine's constants (checked by
  the harness). One text differs from the Hebrew record on purpose: item 009's `informationToBot` names the
  gallon sizes ("2 ליטר ו-5 ליטר").
- Unicode: one option of שאלה 5 stores a shadda before a kasra on screen and after it in the metadata. The two
  are canonically equivalent; the reporting layer compares in NFC and sends the metadata string, and the
  harness compares the same way.
